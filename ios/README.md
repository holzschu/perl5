# Reconstructed a-Shell Perl frameworks

Run `bash build_ios.sh` on macOS with full Xcode. The output is `.build/{perl,perlA,perlB}.xcframework.zip` and `.build/checksums.txt`. Each XCFramework contains arm64 iOS and arm64/x86_64 Simulator slices, with deployment target iOS 14. Build and compiler parallelism is limited to two jobs. Set `PERL_IOS_BUILD_DIR` to put intermediate products outside the checkout.

The public `iOS_1.0` source tag is unmodified Perl 5.35.5, while the binary release and a-Shell's bundled modules are Perl 5.34.0. This recipe therefore downloads the checksum-pinned official 5.34.0 source archive. It reconstructs the unpublished C changes; it does not claim to recover their original source. The original target configuration is recovered from a-Shell's checksum-pinned public `Resources/Perl/Config_heavy.pl`, with obsolete machine paths removed and current SDK/toolchain settings applied. ios_system v3.0.1 and its adapter header are checksum-pinned too.

The recipe builds a same-source native miniperl and `generate_uudmap` in a separate host directory, then uses Perl's existing static-extension build for the target. Darwin's miniperl rule is patched to honor the cross-build host tool. The final framework link includes every archive in the preserved `static_ext` list, `libperl.a` and the generated `ext.libs` flags, with undefined symbols rejected. Target compilation enables `-fstack-protector-strong`. The recipe disables host `pipe2`/`dup3` probes because newer SDK weak symbols can be absent on the running macOS. No target executable is run on the Mac during cross-compilation.

The three frameworks are separate links of the same interpreter and static XS modules. ios_system selects them for nested Perl/CPAN commands, preserving independent interpreter globals. The host entry remains `main`; Perl standard streams own duplicates of ios_system's thread-local stream descriptors. List-form `system` uses `ios_execv`; string-form `system` and command pipes use ios_system. Perl's `fork` is unimplemented (`d_fork` is undefined); ios_system sessions do not provide a child address space.

From a disposable working directory inside an a-Shell app that embeds these frameworks, run `dash /path/to/ios/acceptance.sh`. It checks version, stdin/stdout/stderr bytes, POSIX and File::Spec, exit status including negative child exits, consecutive calls, a pipeline, inherited environment and PERL5LIB, replacement and restoration of `%ENV`, pipe-open failure recovery, missing commands, redirected terminal detection, a delayed nested child's exit status, command-pipe output and status, output ordering, explicit program selection and unbuffered stderr. At the a-Shell prompt, `perl -e 'die "not a terminal\n" unless -t STDOUT'` checks terminal output. The workflow publishes releases only for `v*` tags in `holzschu/perl5` and refuses to overwrite assets.

Hosts embedding only these three frameworks set ios_system's public `numPerlInterpreters` to 3 before running commands. Hosts that also embed `perlC.framework` keep their four-slot configuration.
